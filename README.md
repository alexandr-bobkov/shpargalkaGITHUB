# 📌 Полная шпаргалка по Git: От настройки до командной разработки

## 1. Первая настройка пустого репозитория
*Git не создает ветки, пока в проекте нет хотя бы одного коммита.*

```bash
# Создать стартовый файл
echo "# My Project" > README.md

# Создать главную ветку main и переключиться на нее
git checkout -b main

# Зафиксировать первый файл
git add README.md
git commit -m "Initial commit"

# Отправить ветку main на GitHub и связать ее с сервером
git push -u origin main
```

---

## 2. Управление ветками (`main` и `dev`)

```bash
# Создать ветку dev от текущей и переключиться на нее
git checkout -b dev

# Отправить новую ветку dev на GitHub
git push -u origin dev

# Посмотреть список всех локальных веток (* указывает на текущую)
git branch

# Быстро переключиться на существующую ветку
git checkout main
```

---

## 3. Фиксация изменений в процессе работы

```bash
# Проверить статус файлов (что изменилось, что готово к коммиту)
git status

# Добавить все измененные и новые файлы в индекс
git add .

# Создать коммит локально
git commit -m "Описание изменений"

# Отправить коммиты из текущей ветки на GitHub
git push origin dev
```

---

## 4. Перенос изменений из `dev` в `main` (Слияние)

```bash
# 1. Переключиться на главную ветку
git checkout main

# 2. Скачать последние изменения main с сервера (для профилактики)
git pull origin main

# 3. Влить изменения из ветки dev в ветку main
git merge dev

# 4. Отправить обновленный локальный main на GitHub
git push origin main

# 5. Вернуться обратно в ветку dev для продолжения работы
git checkout dev
```

---

## 5. 🔥 Решение конфликтов слияния (Merge Conflicts)
*Происходит, если один и тот же файл был изменен в main и dev одновременно.*

Если после `git merge dev` вы увидели ошибку `CONFLICT (content): Merge conflict in...`:

1. Откройте конфликтующий файл в редакторе кода (например, VS Code).
2. Вы увидите разметку Git:
   ```text
   <<<<<<< HEAD
   Код, который сейчас находится в main
   =======
   Код, который вы принесли из ветки dev
   >>>>>>> dev
   ```
3. Выберите нужный вариант (или объедините их вручную), удалив маркеры `<<<<<<<`, `=======`, `>>>>>>>`.
4. Завершите слияние командами:
   ```bash
   git add .
   git commit -m "Fix merge conflicts"
   git push origin main
   ```
*Если всё пошло не так и вы хотите отменить слияние:* `git merge --abort`

## 6. 🛠 Откат изменений и исправление ошибок

```bash
# Изменить текст последнего коммита (если еще не делали git push)
git commit --amend -m "Новое правильное описание"

# Отменить git add (убрать файл из индекса, но сохранить код)
git reset HEAD имя_файла.ext

# Полностью стереть все незакоммиченные изменения (ВНИМАНИЕ: код сотрется!)
git reset --hard HEAD

# Вернуть один конкретный файл к состоянию последнего коммита
git checkout -- имя_файла.ext

# Отменить уже отправленный на GitHub коммит (создает зеркальный "отменяющий" коммит)
git revert <хэш_коммита>
```

## 7. 🧹 Удаление старых веток

```bash
# Удалить локальную ветку (после того, как слили её в main)
git branch -d имя_ветки

# Удалить локальную ветку принудительно (если код не был заслит)
git branch -D имя_ветки

# Удалить ветку на самом GitHub
git push origin --delete имя_ветки
```

## 8. ✨ Полезные лайфхаки для удобства

```bash
# Посмотреть красивую историю коммитов в виде графа
git log --oneline --graph --all

# Спрятать незакоммиченные изменения в буфер, чтобы переключить ветки без коммита
git stash

# Вернуть спрятанные изменения обратно и продолжить работу
git stash pop
```

## 9. 👥 На будущее: Совместная работа (Fork & Pull Request)
*Используется, когда вы хотите внести вклад в чужой проект или работаете в большой команде с жестким контролем кода.*

```text
 Схема: [Оригинальный Репозиторий] -> (Нажать Fork на GitHub) -> [Ваша копия репозитория] -> (git clone) -> [Ваш ПК]
```

### Шаг 1. Настройка связи с оригинальным репозиторием
После того как вы сделали `Fork` на GitHub и склонировали **свою** копию к себе на ПК, добавьте ссылку на **оригинальный** (главный) репозиторий под именем `upstream`:
```bash
git remote add upstream https://github.com
```

### Шаг 2. Синхронизация своего кода с чужими изменениями
Перед тем как писать свой код, скачайте то, что успели написать другие участники в оригинальном проекте:
```bash
# Скачать ветку main из оригинального репозитория
git fetch upstream

# Переключиться на локальный main
git checkout main

# Влить изменения из оригинального проекта в свой локальный main
git merge upstream/main
```

### Шаг 3. Отправка своего кода на проверку (Pull Request)
1. Создайте новую ветку для своей задачи: `git checkout -b feature-my-task`.
2. Напишите код, сделайте коммит: `git add .` и `git commit -m "Add new feature"`.
3. Отправьте ветку в **свою** копию на GitHub: `git push origin feature-my-task`.
4. Зайдите на страницу **своего** репозитория на GitHub. Там появится кнопка **«Contribute» -> «Open Pull Request»**.
5. Нажмите её, опишите свои изменения и отправьте на проверку владельцу оригинального репозитория.
